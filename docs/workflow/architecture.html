1 · System Context

Augmented OCR turns vendor PDFs into structured, reviewed, billable JSON. One admin provisions isolated clients; each client owns N vendors (one vendor = one PDF format); every page, token, and millisecond is metered.

2 · Container View

Six processes. Workers never call each other — they coordinate only through the Postgres jobs table with FOR UPDATE SKIP LOCKED. That single decision makes every stage independently scalable and crash-recoverable with no distributed-systems code.

3 · Tenant Isolation Invariant #1

There is no user_id on extractions, jobs, or llm_usage. Ownership is always resolved by walking back to a vendor. Admin role short-circuits every assert.

5 · Pipeline State Machine Invariant #2: page 1 is sequential

normalize fans out to both ocr and llm (PaddleOCR on CPU while Qwen runs on GPU). Whichever finishes last triggers postprocess via an idempotent readiness guard. The LLM stage never sets done — postprocess owns that transition.

stateDiagram-v2 [*] --> normalize normalize --> ocr: scanned pages normalize --> llm: page images ocr --> postprocess: geometry ready llm --> postprocess: result + layout boxes ready postprocess --> done llm --> unverified: page-1 vendor_confirmed=false normalize --> cancelled: cancel requested ocr --> cancelled llm --> partial: cancelled w/ partial results postprocess --> done done --> [*] note right of llm PARALLEL_BATCH = 1 page 1 → header + boxes + vendor verify pages 2+ → line items only per-page token + latency → llm_usage end note

Model strategy. Backend is Qwen3-VL only (llama.cpp, GGUF). Gemini 3 Flash is an optional alternative in the standalone gemini/ folder — same JSON shape, a deployment choice, not runtime-pluggable. Prefer Qwen3-VL while we have GPU; fall back to Gemini 3 Flash only if the customer can't supply adequate GPU (hosted, per-call cost, near-zero infra, scales instantly). Wiring Gemini into the llm stage is a future task, not current behavior.
Box lifecycle (corrected). Every PDF's page 1 goes to the model fresh every run and returns box + value. qwen_layout_boxes is upserted last-write-wins and read back within the same extraction — a per-run LLM→postprocess handoff, not a long-lived cache. No "learned once, reused forever" path exists, so a bad page-1 box cannot be inherited by future documents. The only cross-document reuse is spatial memory (human-corrected regions, never values).

7 · Metering & Billing

Billing is derived, never a stored running total. Source of truth: llm_usage — one row per LLM call (≈ per page) written by the LLM stage as each page completes.

MetricDerivation
Per-page tokens / latencyllm_usage.prompt_tokens · completion_tokens · duration_ms from the model server usage block
Per-PDF totalsget_extraction_token_totals — aggregate by extraction_id
Per-client billable pagesCOUNT(DISTINCT (extraction_id, page_num)) where extraction_id NOT NULL
Quota gateingest rejects with 402 if billable ≥ subscription_limit (soft limit; 0 = blocked)
Known billing leak: llm_usage.extraction_id is ON DELETE SET NULL — deleting an extraction removes its pages from the billable count. Fix = freeze billable pages into an append-only ledger at completion. Tracked, not fixed

8 · Scheduler Concurrency — "Client A & B both at 22:00"

Simultaneous schedules are safe and isolated by design. The only thing that degrades under simultaneous large batches is latency fairness, and that has a designed, tested, gated fix. No client can ever see, block, or corrupt another's data through the scheduler.

10 · Scaling (10 → 100 customers)

The one decision that matters: the model is GGUF → stay on llama.cpp, raise --parallel 1 → 8–16 on a 24–48 GB AWS GPU. Zero Python changes, 5–10× throughput. vLLM is not an option (no GGUF vision support).

Single RTX 4060 ≈ 240 pages/hr (serial — the hard wall). Overnight batch acceptable → steps 1, 3a, 5 on one GPU. Same-hour turnaround → step 4 is mandatory; the queue already load-balances two llm-workers with zero code change. Full detail: docs/scaling.md.

11 · Guardrails — what must never change

  1. Sequential page processing within a document (PARALLEL_BATCH = 1).
  2. FOR UPDATE SKIP LOCKED + jobs_active_idx queue design.
  3. Tenant isolation via vendors.user_id walk — never add a bypass user_id.
  4. Spatial memory stores geometry, not values.
  5. Postprocess — not LLM — owns the final done transition.
  6. Vendor detection never auto-creates a vendor.
  7. Reuse the finalized llama-server flags exactly on any new GPU.
