Tenant isolation rules

  • Every tenant-owned table carries tenant_id.
  • Every storage key is prefixed: tenants/{id}/docs/{doc_id}/
  • Every queue payload includes tenant_id, job_id, document_id.
  • Every log + trace span carries tenant context.
  • Admin bypasses tenant filter explicitly — clients never can.
  • PostgreSQL row-level security strongly recommended.

Scheduler — Client A & B at 10 PM

  • Scheduler only enqueues due work into durable queue.
  • Both clients get independent batch_run records.
  • Worker pool processes both concurrently.
  • Per-tenant fairness limit: max 5 active docs at once.
  • Global GPU workers: 20. Per-doc parallel pages: 4.
  • Use Celery+Redis, Dramatiq, or RQ — not in-process cron.

Hallucination controls for Qwen

  • Strict JSON schema per vendor template.
  • Prompt versioning — immutable template history.
  • Vendor-specific contracts, not one generic prompt.
  • OCR/bbox grounding for extracted field values.
  • Confidence scoring per field.
  • Reject/review rules: impossible totals, missing IDs, invalid dates.
  • Store raw model response separately from normalized output.
  • Track hallucination rate per template + model version.

Edge cases to handle

File issues

  • Corrupted or password-protected PDF
  • Empty PDF
  • Scanned image with no readable text
  • Page rotation or severe skew
  • Duplicate upload detection

Vendor detection issues

  • First page is a cover/title page
  • Vendor not in registered list
  • Mixed-vendor pages in one PDF
  • Low confidence score — needs review threshold

Extraction + system issues

  • Malformed JSON from Qwen
  • Model timeout mid-document
  • Same schedule triggered twice (idempotency)
  • Client hits quota limit mid-job
  • Tenant accesses another tenant's document ID
Scaling plan

Phase 2 — Scale out

Phase 3 — Platform

  • Independent model gateway service
  • Usage analytics warehouse
  • Multi-region storage + DR
  • Billing and quota enforcement
