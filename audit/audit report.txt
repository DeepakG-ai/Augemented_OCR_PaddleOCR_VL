### TIER 1: CRITICAL (Breaks functionality or crashes)

#### 1. `main.py` ~line 1044 — Syntax/Indentation Crash
Inside the SSE async generator, `with trace_extraction_pipeline(` has 10-space indentation instead of 12. Python accepts it but it will cause a runtime IndentationError when this code path executes.

#### 2. `db.py` `ensure_job()` — Race Condition Creates Duplicate Jobs
`ensure_job()` calls `has_active_job()` then `enqueue_job()` as separate steps. Two workers completing simultaneously both see "no active job" and both enqueue the same stage. The `ON CONFLICT DO NOTHING` in `enqueue_job()` only protects within a single transaction — not across the two-step check.

#### 3. `worker.py` `_process_postprocess()` — Can Run Twice Per Extraction
Because `ensure_job()` has the race above, both an OCR and LLM completion can each enqueue postprocess simultaneously. Two postprocess workers can then run on the same extraction.

#### 4. `db.py` `is_postprocess_ready()` — Digital-Only PDFs Stuck Forever
The readiness check requires `ocr_data IS NOT NULL`. For fully digital PDFs, `ocr_data` is never populated. Postprocess is never enqueued. The extraction stays in "processing" state indefinitely.

#### 5. `worker.py` `_stop_if_cancelled()` — Cancelled Extractions Spawn Orphan Jobs
The cancel check stops processing but does NOT prevent the next `ensure_job()` call from firing. Normalize continues to enqueue OCR and LLM stages even after cancel is requested. These orphan jobs run to completion.

#### 6. `extractor.py` line 456 — Crashes on Unexpected LLM Response
`resp_json["choices"][0]["message"]["content"]` assumes the structure without any guard. If the LLM returns `{"error": "..."}` or an empty `choices` array, this throws `IndexError` and the entire page fails with no retry context.

#### 7. `extractor.py` line 735 — Wrong "cancelled" Flag
`"cancelled": cancelled or batch_had_failure` — a JSON parse failure or network timeout sets `batch_had_failure=True`, which then reports the extraction as "cancelled" to the caller. This conflates two completely different failure types and breaks retry logic.

#### 8. `processor.py` line 36 — ThreadPoolExecutor Leaks Forever
`_executor = ThreadPoolExecutor(max_workers=PDF_WORKERS)` is created at module load and never shut down. Worker threads live for the entire process lifetime and prevent clean shutdown.

### TIER 2: HIGH (Silent data loss or wrong results)

#### 9. `extractor.py` `_strip_newlines()` — Destroys Multi-Line Address Fields
Called on every LLM response and merged result. Recursively replaces ALL newlines in the JSON with spaces. A field like `"ship_to": "123 Main St\nSuite 4\nNew York"` becomes `"ship_to": "123 Main St Suite 4 New York"` silently. No way to preserve multi-line fields.

#### 10. `extractor.py` `_combine_header_value()` — Case-Insensitive Deduplication Loses Data
Called during multi-page merge. "Bill To" on page 1 and "BILL TO" on page 3 are treated as duplicates and one is silently dropped. If the value on page 1 says "John Doe" and page 3 says "john doe", one is discarded.

#### 11. `extractor.py` line 818-843 — No Line Item Deduplication Across Pages
When merging multi-page POs, identical line items from continuation pages are appended without checking for duplicates. Final count inflates. No warning is logged.

#### 12. `extractor.py` line 522 — Regex Breaks Valid Numbers
Pattern `r'([\[:,]\s*)(-?0[0-9]+)(\s*[\]},])'` is meant to fix JSON leading-zero errors but is too broad. It transforms `{"po_number": 0012}` into `{"po_number": "0012"}` — type change from int to string — silently.

#### 13. `spatial_memory.py` lines 65-69 — Template Load Failure Bypasses Field Restrictions
If the DB call to load configured header fields throws, the exception is caught at DEBUG level and `configured_header_fields` defaults to an empty set. Empty set means `_is_reusable_header_field()` returns True for ANY field including line items — completely bypassing the header-only restriction.

#### 14. `extractor.py` line 497-498 — LLM Usage Recording Silently Lost
If `db_mod.record_llm_usage()` fails, only a warning is logged. Extraction continues successfully. Token billing data is permanently lost with no retry mechanism.

#### 15. `processor.py` lines 63-64 — Image Upscaling Degrades Quality
`nw = max(32, round(nw / 32) * 32)` uses `round()` (banker's rounding). `nw=97` → rounds to 128, not 96. This upscales images, making OCR text blurry. Should use floor division `//`.

#### 16. `processor.py` lines 107-112 — Corrupt Page Skip Causes Count Mismatch
When a page render throws, the page is skipped and no placeholder is added. But `render_count = min(total_pages, max_pages)` counts ALL pages. Callers receive fewer results than expected, causing index misalignment.

#### 17. `worker.py` line 695 — Page 1 Boxes Lost If Page 1 Failed
If page 1 extraction fails, `next((pr for pr in _page_results if pr.get("_page") == 1 and "_error" not in pr), None)` correctly returns None. But then bbox data is never saved — no retry, no fallback. The document continues with no field_locations from page 1.

#### 18. `worker.py` — Spatial Memory Apply Failure Silently Produces Stale Results
If `apply_to_extraction()` throws inside postprocess, processing continues with the original unmodified `field_locations`. The extraction is marked `done`, but the user's corrections were silently ignored.

#### 19. `exporter.py` lines 72-76 — Non-Dict Line Items Break Column Alignment
If `line_items` contains any non-dict element, it's placed in row position 0 but columns still expect N values. The resulting CSV/Excel has mismatched column widths.

#### 20. `vendor_detector.py` line 248 — No First-Page Enforcement
The docstring says "detect vendor from page-1 words" but the function accepts any word list. If multi-page words are passed by a caller, vendor detection runs on page 2+ text.

### TIER 3: MEDIUM (Logic gaps, auth, missing validation)

#### 21. `main.py` lines 1209-1237 — Soft Quota Race Condition
The page limit check reads `u_used` from DB, checks if `u_used >= u_limit`, then allows the upload. With 10 concurrent uploads each reading `u_used = 990` on a 1000-page limit, all 10 pass — 200+ pages processed above limit. The soft-limit semantics (allow the final overage) are correct, but concurrent bypass is not.

#### 22. `main.py` lines 1967-1985 — Correction Diff Boolean Bug
`if isinstance(original, list) or isinstance(corrected, list):` — uses `or`, not `and`. If only one side is a list, the function enters the list branch and wraps the non-list side incorrectly. Should be `and` to only handle cases where both are lists.

#### 23. `main.py` line 103 — JWT Token in Query String Exposed in Logs
SSE connections send the token as `?token=<JWT>` because EventSource cannot send headers. This token appears in browser history, access logs, CDN logs, and referrer headers. By design, but undocumented risk.

#### 24. `main.py` lines 941-976 — Dead Code Below First HTTPException
The deprecated `/extract` endpoint raises `HTTPException` on line 941, then has 30+ unreachable lines below. `_active_extractions` dict (line 158) is initialized but never used.

#### 25. `main.py` lines 1706-1785 — Extraction Delete Does Not Cascade Jobs
Deleting an extraction removes the extraction row but not the related `jobs` rows. If the extraction is stuck in a crashed `running` state, it can't be deleted (409 guard), and stale jobs accumulate.

#### 26. `db.py` `cancel_jobs_for_extraction()` — "cancelling" Is a Zombie State
Jobs are set to `cancelling` but no code anywhere polls for or transitions out of this state. Jobs stuck in `cancelling` are never recovered, never retried, never failed. The stale recovery threshold (10 min) doesn't handle `cancelling`.

#### 27. `db.py` `recover_stale_jobs()` — Missing `cancelling` State
The stale job recovery query looks for `running` status only. Jobs in `cancelling` state that crash never get recovered.

#### 28. `db.py` line 2207 — Fragile String Parsing of asyncpg Result
`int(result.split()[-1]) if result else 0` assumes asyncpg returns "UPDATE N" format. If the library ever changes its return format, this crashes with IndexError or ValueError silently.

#### 29. `page_logger.py` line 43-45 — `count_result_fields()` Crashes on Non-Dict List
The function iterates a list and calls `.items()` on each element. If the list contains a string or None, it throws `AttributeError`. The check `if isinstance(r, dict)` is missing from the loop body.

#### 30. `page_logger.py` line 88 — `overage` Calculation Semantically Backwards
`overage = subscription_limit - total_extracted_pages` produces a negative number when over limit. The variable name implies "amount over", but it stores "amount remaining (negative)". The value -3 means 3 pages over, not -3 pages.

#### 31. `spatial_memory.py` lines 125-128 — Banker's Rounding Causes Coordinate Drift
Python 3's `round()` uses banker's rounding (0.5 rounds to nearest even). Saved spatial memory boxes can shift 1-2 pixels between save and apply cycles, causing progressively misaligned regions.

#### 32. `layout_key.py` line 39 — `None` vs. `"default"` Collision
`template_id or 'default'` means `compute_layout_key(v_id, None)` and `compute_layout_key(v_id, "default")` produce identical keys. A vendor with no template and a vendor with a template named "default" share spatial memory.

### TIER 4: Frontend Bugs

#### 33. `dashboard.js` / `extract.js` — Global State Never Cleared on Logout
`_clientDashboardData`, `_userDocsData`, `_activeStreamAbort`, and similar module-level variables persist across browser sessions. If Admin A views Client B's data, then Client B logs in from the same browser, stale admin data is still in memory.

#### 34. `vendors.js` lines 113-150 — System Prompt Visibility Enforced Client-Side Only
The frontend hides system prompts based on `isAdmin` read from localStorage. Any user who modifies `role: "admin"` in localStorage sees the prompt HTML. The API correctly withholds prompt content, but the frontend logic is trivially bypassable.

#### 35. `extract.js` lines 706-752 — SSE Race on Concurrent Extractions
`activeJobId` is set at line 693 and cleared at line 742. Two rapid extraction starts from the same tab cause the second to overwrite `activeJobId`, losing track of the first stream.

#### 36. `review.js` — No Unsaved Changes Warning
`_rvDirty` is tracked but never checked before navigation. Edited correction fields are silently discarded if the user clicks back.

#### 37. `extract.js` lines 487-592 — Pipeline Stage Order Hardcoded
The visual stage progression is a hardcoded array `['upload', 'detect', 'normalize', 'ocr', 'llm', 'json', 'postprocess']`. If the backend sends stages out of expected order (e.g., on retry), the UI marks them all done regardless.
