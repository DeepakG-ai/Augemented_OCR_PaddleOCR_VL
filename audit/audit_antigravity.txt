SECTION 1: CLAUDE CODE REVIEW (Findings #1–37)
================================================================================

#1  main.py ~1044 indentation crash
    ❌ WRONG
    Line 1044 uses 2-space indent inside try: block. Python accepts consistent
    2-space indentation. Also this is inside the DEPRECATED /extract endpoint
    which returns 410 Gone at line 941. This code path is never reached.

#2  db.py ensure_job() race condition creates duplicate jobs
    ❌ WRONG
    enqueue_job() at db.py:2043 uses ON CONFLICT (extraction_id, job_type)
    WHERE status IN ('queued','running') DO NOTHING. This is a DATABASE-LEVEL
    partial unique index — it blocks duplicates across ALL concurrent
    transactions atomically. The has_active_job() pre-check is just an
    optimization to avoid the INSERT attempt.

#3  worker.py postprocess can run twice
    ❌ WRONG
    Follows from #2 being wrong. The DB constraint prevents duplicate
    postprocess jobs.

#4  db.py is_postprocess_ready() — digital PDFs stuck forever
    ❌ WRONG — BIGGEST FABRICATION
    worker.py:419-430: When all pages are digital, _process_ocr explicitly
    builds unified geometry from word_geometry and calls
    save_ocr_data(pool, extraction_id, unified). ocr_data IS populated
    for digital PDFs.

#5  worker.py cancelled extractions spawn orphan jobs
    ✅ CONFIRMED (low probability)
    _stop_if_cancelled() is checked before ensure_job() calls, but a cancel
    request arriving between the check and the enqueue creates orphan jobs.

#6  extractor.py:456 crashes on unexpected LLM response
    ✅ CONFIRMED
    resp_json["choices"][0]["message"]["content"] has no guard. If LLM
    returns {"error":...} or empty choices, throws KeyError/IndexError.
    The outer except does NOT catch these types.

#7  extractor.py:735 wrong "cancelled" flag
    ✅ CONFIRMED
    "cancelled": cancelled or batch_had_failure — a JSON parse failure
    sets batch_had_failure=True, reported as "cancelled". Conflates
    failure with cancellation. Worker sets status "partial" based on this.

#8  processor.py ThreadPoolExecutor leaks forever
    ❌ WRONG
    Module-level executor in a long-running uvicorn server is STANDARD
    PRACTICE. It lives for process lifetime by design. Not a leak.

#9  extractor.py _strip_newlines() destroys multi-line addresses
    ⚠️ PARTIAL
    True that all newlines are replaced. But LLM returns single-line
    values by design. This is intentional JSON safety, not a bug.

#10 extractor.py _combine_header_value() case-insensitive dedup
    ⚠️ PARTIAL
    Uses casefold() for dedup. This is CORRECT for merge use case — page 1
    says "JOHN DOE", page 2 says "John Doe" — keep one. By design.

#11 No line item deduplication across pages
    ⚠️ PARTIAL
    Line items are intentionally appended across pages (page 1 rows 1-10,
    page 2 rows 11-20). For single_po_multipage this is correct behavior.

#12 Regex breaks valid numbers
    ⚠️ PARTIAL
    The regex only fires when JSON is ALREADY invalid (leading zeros).
    Type change from int to string is acceptable since the alternative
    is complete parse failure. Recovery mechanism, not a bug.

#13 spatial_memory.py template load failure bypasses field restrictions
    ✅ CONFIRMED
    spatial_memory.py:65-69: If DB call throws, configured_header_fields
    defaults to empty set. Empty set means _is_reusable_header_field()
    returns True for ANY field including line items at line 80-83.

#14 LLM usage recording silently lost
    ⚠️ PARTIAL
    By design — billing log failure should not crash extraction. But yes,
    billing data is lost with no retry. Acceptable tradeoff.

#15 processor.py round() upscaling degrades quality
    ❌ WRONG
    Claim says nw=97 rounds to 128. WRONG MATH: round(97/32) = round(3.03)
    = 3, so 3*32 = 96, not 128. Banker's rounding only affects exactly .5
    boundaries — negligible on ~1000px images.

#16 Corrupt page skip causes count mismatch
    ⚠️ PARTIAL
    Skipped pages do produce fewer results. But worker.py iterates
    rendered_pages (actual results), not range(total_pages). Not as
    dangerous as claimed.

#17 Page 1 boxes lost if page 1 failed
    ⚠️ PARTIAL
    True, but correct behavior — you can't save boxes from a failed page.

#18 Spatial memory apply failure silently produces stale results
    ✅ CONFIRMED
    If apply_to_extraction() throws in postprocess, extraction completes
    with pre-spatial-memory results. User's corrections silently ignored.

#19 exporter.py non-dict line items break column alignment
    ✅ CONFIRMED
    exporter.py:72-76: Non-dict item creates 1-element row but columns
    may have 5+ columns. Misaligned CSV/Excel. Unlikely in practice.

#20 vendor_detector.py no first-page enforcement
    ❌ WRONG
    The function accepts any word list, but ALL callers pass page 1 words
    only. Enforcement is at caller level. Not a bug.

#21 Soft quota race condition
    ✅ CONFIRMED
    10 concurrent uploads can all pass the check simultaneously. But since
    this is a soft limit by design, slight overshoot is acceptable.

#22 Correction diff boolean bug (or vs and)
    ❌ WRONG
    main.py:2005: "or" is CORRECT. If EITHER side is a list, you need list
    handling. Lines 2006-2007 coerce the non-list side safely.

#23 JWT token in query string
    ✅ CONFIRMED
    Known limitation of SSE/EventSource API. Documented and accepted risk.

#24 Dead code below HTTPException
    ✅ CONFIRMED
    Real dead code in deprecated endpoint. Harmless but should be cleaned.

#25 Extraction delete does not cascade jobs
    ✅ CONFIRMED
    db.py:1805-1812: Only deletes extraction row. Jobs, pages remain.

#26 cancel_jobs_for_extraction — "cancelling" zombie state
    ❌ WRONG — FABRICATED
    Function cancel_jobs_for_extraction() DOES NOT EXIST in db.py.

#27 recover_stale_jobs missing cancelling state
    ❌ WRONG
    Follows from #26 being fabricated.

#28 db.py fragile string parsing of asyncpg result
    ❌ WRONG
    db.py:1788 uses result == "UPDATE 1" — direct string equality check,

#29 page_logger.py count_result_fields crashes on non-dict
    ❌ WRONG
    page_logger.py:44-46: The guard IS present: "for r in result
    if isinstance(r, dict)" — the isinstance check is in the generator.

#30 overage calculation semantically backwards
    ✅ CONFIRMED (cosmetic)
    page_logger.py:95: overage = subscription_limit - total_extracted_pages.
    Variable named "overage" but value is "remaining". Docstring at line

#31 Banker's rounding coordinate drift
    ❌ WRONG
    Spatial memory uses normalized 0.0-1.0 floats, not integer pixels.
    Sub-pixel drift is invisible.

#32 layout_key None vs "default" collision
    ❌ WRONG
    Template IDs are integers, never the string "default". Collision is
    theoretically possible but impossible in practice.

#33 Frontend global state not cleared on logout
    ✅ CONFIRMED
    Module-level vars persist in browser tab across sessions.

#34 System prompt visibility client-side only
    ✅ CONFIRMED
    Frontend check is bypassable via localStorage. But the API correctly
    withholds prompt content for non-admins. Server-side is secure.

#35 SSE race on concurrent extractions
    ✅ CONFIRMED
    activeJobId overwrite on rapid extraction starts.

#36 No unsaved changes warning
    ✅ CONFIRMED
    _rvDirty tracked but never checked before navigation.

#37 Pipeline stage order hardcoded

    Hardcoded array but stages always arrive in order. Edge case only.

DESIGN DECISIONS (not bugs — intentional behavior)
================================================================================

1. Fuzzy vendor detection fallback is BY DESIGN for usability.
   If strict exact-match is required, remove _detect_fuzzy() call.

2. _strip_newlines() is intentional JSON safety. LLM returns single-line values.

3. Case-insensitive header dedup in merge is correct for multi-page merging.

4. Module-level ThreadPoolExecutor is standard for long-running servers.

5. ON CONFLICT DO NOTHING in ensure_job() IS database-level atomic protection.
   The has_active_job() pre-check is an optimization, not the real guard.

6. Value-redacted gold hints FOLLOW AGENTS.md §2-3. Not a spec violation.

7. layout_key = vendor_id:template_id is acknowledged Phase 1 limitation.
